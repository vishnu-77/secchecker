02 / WHAT IT INSPECTS
01

Prompt & context

Selected user-controlled data entering privileged prompts, delimiter manipulation and sensitive-context flows.

02

MCP & tool trust

Poisoned tool descriptions, untrusted metadata, tool results re-entering privileged context and selected execution boundaries.

03

Model output

Selected model- or tool-controlled values reaching eval, exec, subprocess, shell and other dangerous sinks.

04

Agent memory

User-controlled or untrusted content written directly to selected persistent-memory and vector-store patterns.

05

Agent control flow

Selected unvalidated function-call results, recursive invocation patterns and autonomous loops without clear exit conditions.

06

AI credentials

Context-aware checks for selected provider credentials, including how material is declared and passed to clients.

04 / METHODOLOGY
RESEARCH QUESTION

How effectively can static analysis identify security conditions introduced by AI-native applications before deployment?

01PAIR

Each regression vulnerability has a safe twin with the vulnerable line replaced while the surrounding fixture stays comparable.

02SCAN

Scoring is deterministic and offline. No LLM judge decides whether a finding counts.

03SEPARATE

Regression, adversarial, benign-realistic and real-repository evidence are reported separately because they answer different questions.

04TRIAGE

Real-repository findings are manually reviewed so false positives and structural coverage gaps are visible rather than hidden.

05 / WHERE IT FITS

A focused AI-security static analyser, not a claim to understand your entire system.

SecChecker is most useful as one layer in an engineering security workflow: early, local and deterministic. Runtime authority, exploitability and whole-program behaviour need other controls.

SECHECKER DOES
  • Inspect selected AI trust-boundary code shapes
  • Analyse prompt, MCP, tool, memory and output patterns
  • Use Python structure for selected contextual checks
  • Produce CI-friendly SARIF and machine-readable reports
  • Run without sending source to an LLM analysis service
SECHECKER COMPLEMENTS
  • Code review and threat modelling
  • Semgrep, CodeQL and mature general-purpose SAST
  • Secret and dependency scanners
  • Red-team and adversarial testing
  • Runtime policy and agent governance
NOT CLAIMED
  • Whole-program interprocedural understanding
  • Runtime enforcement or live tool interception
  • Proof that a reported condition is exploitable
  • Proof that a clean repository is secure
  • Complete semantic coverage of every AI framework
06 / USE IT
